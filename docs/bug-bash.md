# Bug Bash — 2026-09-03

Full-codebase sweep across backend lambdas/infra, frontend core/auth, Survivor/Muk Hunt/Recipes, and the BattleTD Phaser game. Ordered by priority (severity, then blast radius). Fix difficulty: **Trivial** (<5 min, obvious one-liner), **Easy** (<30 min, self-contained), **Medium** (a few places or some design thought), **Hard** (architectural change / deep investigation).

Status column is updated as items get fixed during the bash.

## Critical

| # | Bug | Severity | Difficulty | Status |
|---|-----|----------|------------|--------|
| 1 | **Admin authorization gate is a no-op.** `lib/lambda/middleware.ts:14` — `requireGroup("Admins")` calls `return deny();` inside a Middy `before` middleware, but Middy v5 ignores a `before` handler's return value; short-circuiting requires setting `request.response`. Every route gated only by this middleware is reachable by **any authenticated user**, not just admins: editing/deleting arbitrary blog posts (`posts.ts:284-286`), uploading arbitrary files / listing all images (`images.ts:138-151`), creating/deleting Muk Hunt clues and viewing all submissions (`mukhunt.ts:715-721,738-740`). | Critical | Trivial | ✅ Fixed |
| 2 | **Survivor prediction reminder emails are permanently broken.** `lib/lambda/survivor.ts:742-746` — the `.filter()` callback is block-bodied with no `return`, so it always returns `undefined`/falsy, making `usernamesWithoutPrediction` always empty. `SendEmailCommand` is then called with an empty `ToAddresses`, which SES rejects; unlike sibling handlers there's no try/catch, so the exception propagates and the Step Functions execution fails every time it runs. The "remind players before predictions close" feature is silently dead. | Critical | Trivial | ✅ Fixed |
| 3 | **BattleTD Phaser game instance is never destroyed.** `frontend/src/pages/BattleTDPage.vue` — `game.launch()` runs in `mounted()` but there's no `beforeUnmount`/`unmounted` hook calling `game.destroy(true)`. Every visit to the page leaves a full running Phaser instance (render loop, physics, WebGL context) alive in memory; repeated visits stack up multiple untorn-down game loops running simultaneously. | Critical | Easy | Open |

| 6 | **Uploaded images are stored with the wrong Content-Type.** `frontend/src/pages/EditorPage.vue:98-104` and `frontend/src/pages/recipes/RecipeEditorPage.vue:279-283` — the presigned S3 `PUT` hardcodes `"Content-Type": "multipart/form-data"` while the body is the raw `File` object. | 7 | **Local CDK deploy can ship a stale/empty frontend build.** `lib/ps-website-stack.ts:74-88` — `exec('npm --version')` and `exec('npm i && npm run build', ...)` are fire-and-forget (no callback, not awaited), and `fs.copySync(dist, outputDir)` runs immediately after. | 8 | **BattleTD wave sizing is wrong for the whole game.** `frontend/src/phaser/battletd/scenes/GameScene.ts:143` — `spawnWave(enemyType, waveNumber)` passes `waveState.waveNumber` as the wave size instead of the rank-scaled `waveState.enemyCount` computed by `GameSimulator.getEnemyCount()` (which is then never used). Enemy count grows linearly with wave number instead of following the intended rank scaling — a Boss-rank and Soldier-rank wave at the same wave number spawn identically. | High | Trivial | ✅ Fixed |
| 9 | **Tower projectile lead-targeting math is wrong.** `frontend/src/phaser/battletd/gameobjects/Tower.ts:174` — the quadratic intercept formula computes `a` as `velocity.x + velocity.x + velocity.y * velocity.y - projectileSpeed * projectileSpeed`; the first term should be `velocity.x * velocity.x` (squared), not added twice. Towers consistently mis-lead their shots against moving (especially diagonal/fast) monsters and miss. | High | Trivial | ✅ Fixed |
| 10 | **Shop purchases allow unlimited negative gold.** `frontend/src/phaser/battletd/scenes/GameScene.ts:200-205` (`buyCard()`) and `frontend/src/components/battletd/Shop.vue` — gold is deducted with no check that the player can afford the card, in either the scene or the UI. | 11 | **Leaderboard graph always renders stale data.** `frontend/src/components/survivor/LeaderboardGraph.vue:24-29` — the `leaderboardData` watcher is declared `(oldData, newData)`, but Vue always calls watch callbacks as `(newVal, oldVal)`.
